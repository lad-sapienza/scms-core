# RedirectPage Component

A static, client-side redirect stub for static hosts (GitHub Pages, S3, any
CDN without server-side redirect support). Renders a page that redirects via
`<meta http-equiv="refresh">`, a `<link rel="canonical">` for search engines,
and a `window.location.replace()` fallback for browsers that ignore
meta-refresh.

## When to use this vs. Astro's native `redirects`

Astro's [`redirects`](https://docs.astro.build/en/reference/configuration-reference/#redirects)
config option generates the same kind of stub automatically for `output:
'static'` sites, and should be preferred whenever it applies — it's zero
extra code. Reach for `RedirectPage` only when `redirects` can't express the
mapping.

**Works fine with native `redirects`:** a static source path redirecting to
a destination produced by a dynamic route, as long as the destination is
given as a concrete, already-resolved path (not a bracketed route pattern).
Astro only validates dynamic-parameter propagation when the *source* path
itself has dynamic segments — a static source skips that check entirely.
Confirmed empirically against Astro 7.2.4 (`output: 'static'`): a source
route with no params, e.g. `/chi-siamo`, redirecting to `/it/chi-siamo`
(itself generated by a `src/pages/[locale]/chi-siamo.astro` with
`getStaticPaths`), builds and emits the expected redirect stub with no
errors.

```js
// astro.config.mjs
export default defineConfig({
  redirects: {
    '/chi-siamo': '/it/chi-siamo',
    '/notizie': '/it/notizie',
  },
});
```

**Needs `RedirectPage` instead:** the source path itself is dynamic — e.g.
one redirect per old article slug, `/notizie/<slug>` → `/it/notizie/<slug>`
— *and* the destination route has a dynamic parameter the source doesn't
carry (typically a locale prefix). Astro requires the destination's dynamic
parameters to already be present in the source; `[locale]` isn't, since the
old flat URL had no locale segment. Trying to force it fails at build time:

```js
redirects: {
  '/notizie/[...slug]': '/it/notizie/[...slug]', // does NOT match the
  // registered `/[locale]/notizie/[...slug]` route — this throws
  // InvalidRedirectDestination: "The destination ... does not match any
  // existing route in your project."
}
```

There's no config-level way to say "always substitute `it` for `[locale]`
here" — the list of old slugs to redirect, and the mapping to each new URL,
has to come from actual code that knows about the content collection. That's
what the recipe below does.

## Basic usage — single static redirect

For a handful of one-off redirects where you'd rather not touch
`astro.config.mjs` (or where the source **is** dynamic but happens not to
need a config-level `redirects` entry), drop a page using `RedirectPage`
directly:

```astro
---
// src/pages/chi-siamo.astro
import { RedirectPage } from '@lad-sapienza/scms-core';
export const prerender = true;
---
<RedirectPage target="/it/chi-siamo" />
```

## Recipe — redirecting every entry of a content collection

The common case: a collection is moving from a flat URL (`/notizie/<slug>/`)
to a locale-prefixed one (`/it/notizie/<slug>/`), and every existing entry
needs its own redirect stub. Generate one page per old slug with
`getStaticPaths`, reading the slug list straight from the collection so the
redirect list can never drift out of sync with the content itself:

```astro
---
// src/pages/notizie/[...slug].astro
import { RedirectPage } from '@lad-sapienza/scms-core';
import { getCollection } from 'astro:content';

export const prerender = true;

export async function getStaticPaths() {
  const articles = await getCollection('notizie');
  // Adapt this to however your entry IDs encode locale/slug — e.g. if
  // content lives under src/content/notizie/it/<slug>/, split the id
  // yourself and keep only the default-locale entries (each locale has the
  // same slug, so the redirect only needs to be generated once).
  return articles
    .filter((a) => a.id.startsWith('it/'))
    .map((a) => ({ params: { slug: a.id.slice('it/'.length) } }));
}

const { slug } = Astro.params;
---
<RedirectPage target={`/it/notizie/${slug}/`} />
```

Repeat one such `[...slug].astro` per collection that needs migrating
(`blog`, `ricerca`, `didattica`, ...) — the body only changes in the
collection name and the target prefix. A collection's own `index.astro`
(the old flat listing page) is a single static redirect and can either use
this same component directly or, per the section above, a plain
`redirects` config entry.

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `target` | `string` | — | Destination URL to redirect to (required) |
| `title` | `string` | `"Redirecting…"` | Page `<title>`, shown briefly before the redirect fires |
